# 権利とレビュー

Reading Packのライセンスは、入力した書籍や生成した読解パックの利用権を与えない。権利関係は書籍ごとに確認する必要がある。

## リポジトリ内のライセンス

| 対象 | ライセンス |
|---|---|
| Pythonコード、CLI、検証処理、テスト | MIT |
| 仕様、文書、スキーマ、プロンプト、README | CC BY 4.0 |
| 架空の作例Clockwork Garden | CC0 1.0 Universal |
| 利用者の原稿、構造化データ、生成した読解パック | その書籍の権利者が決める |

文書の著作権者はKoichi Takahashi / 高橋恒一、著作年は2026年である。Creative Commonsライセンスをソフトウェアへは適用しない。Apache-2.0に含まれる明示的な特許許諾は、別の方針判断を要するため現版では採用していない。

## 素材ごとの確認

少なくとも次の八項目について、利用できる範囲を確認する。

1. 書名、副題、章節見出し。
2. ページ情報と刊行メタデータ。
3. 著者が作成した要約と訂正。
4. 用語集と索引の見出し語。
5. 正準命題と確実性に関する情報。
6. 表紙、ロゴ、引用、画像、第三者の文章。
7. 翻訳と翻訳見出し。
8. 外部リンクと転載する説明文。

許諾の範囲を超える素材は公開物から除く。書籍を刊行する権利が、構造化した派生物の公開まで当然に含むとは限らない。自作の本文であっても、そこに含まれる第三者の引用や画像には別の権利がある。

## 機密性と外部AI

読解パックは手作業だけでも完成できる。未刊原稿や抜粋を外部AIへ送る場合は、第一に出版契約と守秘義務、第二に保存期間と学習利用、第三にデータの所在とアカウント設定を確認する。権限が不明なら、出版社または共著者へ先に確認する。ローカルのCLIはデータを外部へ送信しない。

リポジトリ内のプロンプトは、入力する本文を最小限に抑え、長文の再構築を禁じ、出力を候補として扱う。ただし、外部事業者のデータ取扱方針までは強制できない。

## 著者レビュー

著者は、文言、欠落、確実性区分、反証・再検討条件、誤読への応答、人名、用語、翻訳を確認する。同時に、公開物の総体から原著の代わりとなる文章を再構築できないかも判断する。

承認は特定の版と内容ハッシュに結び付く。原資料を改訂した後へ自動的に引き継がない。

## 出版社レビュー

出版契約、書籍由来の情報、ブランド、翻訳権、流通関係に関わる場合は、出版社の確認を受ける。`not_required`は、人が契約と事情を検討して「不要」と判断したことを表す。「まだ尋ねていない」という意味ではない。判断理由をレビュー記録へ残す。

## 再構築不能性レビュー

この検査では`SYS`の指示に頼らない。データ部分だけをモデルへ渡して代替章を作らせ、人間が論証の順序、事例、比喩、文体、読書を代替する充足を回復していないかを判定する。判定基準は実施前に固定する。

不合格なら、公開する情報を減らす。AIへの指示を強めても、情報そのものが残っていれば境界は守れない。

## 公開判断

`publication_decision = approved`を設定するのは人間である。`reading-pack check --release`は判断と前提が現在の正本へ記録されているかを確認するが、公開の可否は決めない。
