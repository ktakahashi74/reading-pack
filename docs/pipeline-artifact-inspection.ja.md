# 候補内容の直接検査

Reading Packの収録内容を原典と照合する。M4は検査対象と完了範囲の台帳、M5は内容の直接検査を実装する。対象候補を変更せず、検査一覧、原典範囲、実施結果と証拠をrun内へ保存する。

この入口は`artifact-acceptance-1`専用である。[制作全体](pipeline-artifact-workflow.ja.md)は内容・指示・配布物の検査、修正、最終記録、著者確認票を接続する。旧runの判定を読み替えず、合否はモデルの回答試験から独立している。

## 1. 準備と実行

まず新契約のrunを`pipeline start --prepare-only`で作成する。recipe、本文、候補プロジェクトの指定方法は[契約選択](pipeline-contract-selection.ja.md)と[自動制作](automatic-pipeline.ja.md)を参照する。候補のプロファイルはrecipeの固定値と一致させる。`auto`は使用できない。

検査一覧を保存するだけなら、モデルを呼ばない。

```sh
reading-pack pipeline inspect-artifact --run private/run --project draft-project --prepare-only
```

内容の意味検査には、設定済みのjudge adapterを使う。資源枠のないrecipeでは実験実行を明示する。

```sh
reading-pack pipeline inspect-artifact --run private/run --project draft-project --experimental
```

実行は固定した資源枠、工程別予約、累計期限を保持する。資源枠のないrecipeだけ、明示した`--experimental`を必要とする。[資源と制作の契約](pipeline-artifact-workflow.ja.md)を参照する。

終了コード0は準備または予定した検査処理の終了を表す。品質合格ではない。返却JSONの`acceptance.status`と`execution.status`を別々に確認する。

## 2. 検査一覧と証拠

候補の全収録項目、原典から導く章の案内要件、項目間の整合を固定IDで登録する。構造・メタデータ、必須module、出典位置、長さは機械検査へ分ける。共通指示・書籍固有差分、最終配布物・採用経路も固定した検査対象に含む。

意味検査は、収録した数値・比較・帰属・引用を含む原典忠実性、重要条件・例外・確実性、章の主要論点への案内、全体の整合を扱う。生成側が選んだ短い引用だけで完了させず、対応する原典の文脈を渡す。本文と著者資料の役割を保持し、補足を本文の自動的な訂正や著者承認として扱わない。

検査応答は各`check_id`の結果を明示する。省略されたIDは未検査のままである。証拠には、当該要求で渡した原典のspan IDを使い、controllerがhash、位置、引用本文を照合する。未知ID、範囲外の引用、重複した結果は拒否する。欠陥には対象または固定要件、基準、原典・構造の証拠、読解への影響を必要とする。

章構造は、保存済みの原典outline、またはMarkdown・Orgの決定的な見出し抽出から得る。他形式で信頼できるoutlineがない場合、章の案内検査は未完了にする。全体整合は全収録内容と全登録資料を一緒に検査する保守的な実装であり、大きな原典では文脈上限により未完了となる。

原典の必要範囲を固定上限内で渡せない場合は、黙って切り詰めず未完了を記録する。確認できない所在や不足した構造情報も未解決として残す。抜粋に見当たらないだけでは捏造と判定しない。詳細の網羅や生成設問への全問正答を新しい採録義務にしない。

モデルによる意味判断は見落としうる。位置・hash・引用照合の成功は、推論の正しさや実書籍全体の品質を証明しない。

## 3. 保存・再開・四状態

保存先はrun内の`acceptance/inspections/<inspection_id>/`である。

- `candidate/`: 変更しない候補のスナップショット。
- `inventory.json`、`plan.json`: 対象、検査ID、資料範囲、候補・資料・設定とのhash結合。
- `evidence/`: 検査ごとの結果。意味検査は保存済みworker要求・応答にも結合する。
- `reports/`: 追記式の台帳・検査報告。直前の報告と証拠を参照する。

同じ候補・設定の再実行は、検証済みの結果とworker応答を再利用する。完了した検査を再呼出しせず、応答が省略した項目を勝手に埋めない。候補変更は別の`inspection_id`になり、旧候補、旧報告、著者の判断を上書きしない。証拠の削除や改変を検出した場合、過去の合格を現状の合格として表示しない。

合否の優先順位は、確認済み欠陥があれば`fail`、未着手は`not_run`、検査未完了または疑義未解決は`inconclusive`、必要な検査完了かつ欠陥・疑義なしは`pass`である。欠陥と未検査範囲は併記する。指示と配布物の必須検査も完了するまで、全体`pass`にはならない。

検査報告とM1の最終記録は別に保存する。[制作全体](pipeline-artifact-workflow.ja.md)では配布物、修正履歴、著者確認票を接続する。単独検査ではモデル診断を`not_run`、著者承認を`not_requested`とする。
