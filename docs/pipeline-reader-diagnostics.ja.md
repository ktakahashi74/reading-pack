# 回答試験とPack合否の分離（M3）

`artifact-acceptance-1`では、モデルの誤答だけを理由にPackを不合格にしない。正答した場合も、Pack自体の欠陥を免除しない。M3はこの境界を評価処理へ接続した段階であり、直接検査全体の完成ではない。

| 対象 | 新契約の動作 | 従来契約 |
|---|---|---|
| 標準制作の設問生成 | 設問を生成・保存せず空のsuiteを返す | 固定development/holdoutを維持 |
| 標準制作の回答評価 | workerを呼ばず`reader_diagnostics / not_run`を返す | 従来の回答・採点・合否を維持 |
| 単問・バッチの評価部品 | 結果をモデル診断として返す | 従来の`passed`・`failures`を維持 |
| 原典監査の要件 | 設問・回答結果を必須内容や監査契約のhashへ取り込まない | 元の固定契約を維持 |
| 著者確認票 | 旧方式の回答成功から新契約の確認票を作る経路を拒否 | 既存の条件を維持 |

新しい診断結果は`kind = reader_diagnostics`を持ち、Pack合否用の`passed`・`failures`を持たない。誤答、採点の不確実性、critical error、採点者の指摘は、ケース・反復に対応する観測として保持する。`critical_errors`は実際のcritical指摘数、`uncertain_grades`は不確実な採点数として分ける。診断の完了は品質合格ではない。診断だけでは原因をモデル側またはPack側へ断定しない。

対象Pack、設問集合、モデル設定への結び付きと回答引用の照合を維持する。不正な引用・出典、バッチ内の設問取り違え、要件数の不一致は従来どおり拒否し、診断完了へ読み替えない。実行中断時の保存済みjobや資源記録も、成功した診断の代用にしない。

新規runの目的契約は`reader-utility-artifact-1`とし、直接検査による合否と任意診断を区別する。中心的意味、条件、原典忠実性、具体的な所在案内の要件は維持する。旧runは元の目的契約を保持し、旧判定や保存済み回答を新基準で書き換えない。

## 現在の実行範囲

[直接検査による制作](pipeline-artifact-workflow.ja.md)では、内容の検査台帳、指示、配布物、固定修正工程、M1形式の著者記録まで接続した。標準制作では回答試験を呼ばない。単問・バッチ診断は独立した部品として維持し、新しい診断CLIや実モデル試験は追加しない。従来方式の回答成功から新契約の著者確認票へ入る経路も拒否する。合成応答による分離の検証は、実書籍やモデルの品質を証明しない。
