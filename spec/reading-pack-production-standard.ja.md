# Reading Pack制作標準 1.0-draft（beta）

日本語版を本標準の正本とする。規範語には「必須（MUST）」「禁止（MUST NOT）」「推奨（SHOULD）」「任意（MAY）」を用いる。草案期間中は要件が互換性なく変わる可能性がある。

## 0. 適用範囲

**RPP-001** 本標準が定めるのは、Reading Packを根拠付きで制作し、人間が確認し、評価して公開する工程である。完成ファイルの形式は[Reading Pack形式仕様](reading-pack-format-spec.ja.md)が定める。特定のCLI、プログラミング言語、AI model、事業者、内部データ構造は要求しない。

**RPP-002** 制作適合は、形式適合から独立して判定しなければならない。本標準へ適合しない工程で作られた形式適合Packを否定してはならず、形式適合だけから制作適合を推定してはならない。

## 1. 制作等級

**RPP-003** 制作等級は次の三段階とする。上位等級は下位等級の要件を含む。

| 等級 | 最低限含む機能 | 必要な人間の確認 |
|---|---|---|
| Level 1 | 書誌と章節の所在案内 | 構造、書誌、権利、非再構築性、公開判断 |
| Level 2 | Level 1に加え、書籍に応じた要約、索引、読解上の論点または参照先 | 内容、帰属、限定、索引説明、公開条件 |
| Level 3 | Level 2に加え、記述／規範を区別した正準命題と、採用する場合は確実性区分、反証・再検討条件 | 命題、確実性、条件、反証・再検討条件 |

**RPP-004** 等級は情報量の点数ではなく、制作した機能と確認範囲の宣言である。書籍の種類に不適切なmoduleを件数稼ぎのために追加してはならない。

## 2. 工程と責任主体

**RPP-005** 制作はW0からW13を用い、D（再現可能な処理）、L（検査を伴うmodel支援）、R（人間または監査可能なAIによる候補の一次選別）、H（softwareに代行させない人間の判断）を区別しなければならない。

| 工程 | 内容 | 主な主体 | 必須出力または判定 |
|---|---|---|---|
| W0 | 設計制約 | H | 対象、権利、言語、等級、profile、評価下限 |
| W1 | 書誌 | D → H | 照合済み書誌 |
| W2 | 確実性 | L → H、任意 | 著者が採用する区分 |
| W3 | 章節地図 | D/L → R/H | 原資料へ結び付いた構造 |
| W4 | 正準命題 | D/L → H、任意 | 帰属、種別、所在、条件 |
| W5 | 人名 | L → R/H、任意 | 本書内での位置付け |
| W6 | 用語 | L → R/H、任意 | 本書内での意味 |
| W7 | 読解上の論点 | L → H、任意 | 分類済みの論点と応答 |
| W8 | AI向け規則 | H | SYSと本書固有方針 |
| W9 | 参照先 | D → H、任意 | 関係と公式性を確認したREF |
| W10 | 組立 | D → H | 検証済み形式適合候補 |
| W11 | 評価 | L → H | 事前基準に対する実測記録 |
| W12 | 著者レビュー | H | 修正、承認、保留の証拠 |
| W13 | 公開と版管理 | D + H | 公開判断、版、配布先、変更履歴 |

**RPP-006** W0、W11の最終判定、W12、W13の公開判断を自動化してはならない。AIは判断材料の抽出、説明、候補作成、回答欄の記入補助を行ってよいが、人間の同意を生成してはならない。

## 3. 品質計画と正本

**RPP-007** 制作開始時に、書籍の種類と用途に応じた品質profile、対象範囲、責任主体、ネタバレ方針、言語、等級、必須module、権利境界、容量上限、非再構築性の基準、評価下限を記録しなければならない。適合は必須gateの論理積で判定し、平均点で重大な欠落を相殺してはならない。

**RPP-008** 編集する正本と配布する生成物を分離しなければならない。同じ正本、設定、templateから同じbyteのPackを再生成でき、生成物の直接編集を検出できなければならない。

**RPP-009** 正本recordは安定ID、状態、来歴を持たなければならない。自動処理はrecordを`approved`にしてはならない。原資料、構造、意味、翻訳元の変更で影響を受けた承認は古いものとして解除しなければならない。

## 4. 取込、候補、根拠

**RPP-010** 原資料の取込は、正本を変えない計画と、明示的な適用に分けなければならない。計画は本文を保持せず、原資料の識別情報、hash、構造、所在、確度、診断だけを含めなければならない。適用直前に原資料と正本の鮮度を再検査しなければならない。

**RPP-011** AIまたは外部処理が作る内容は、正本外の候補として扱わなければならない。採用可能な候補は、原資料hash、候補hash、一つ以上の上限付き根拠範囲へ結び付け、自動検査後も`ready_for_review`を越えてはならない。

**RPP-012** 根拠検査は、指定範囲が指定原資料に存在し、候補が変わっていないことを確認する。候補の正しさ、完全性、帰属、解釈の妥当性を証明したと説明してはならない。確定した公開来歴に原資料の抜粋を残してはならない。

**RPP-013** 候補の一次選別はcandidate IDと内容hashへ結び付けて記録しなければならない。AI一次選別を使う場合はmodel、設定、方法、時刻、候補と根拠のhashを記録する。どちらの一次選別も著者最終レビューの代わりにはならず、適用後のrecordは`draft`でなければならない。

**RPP-014** 人名・用語の説明は本書内での意味または役割を上限付きで抽象化し、原資料の連続複製を検査しなければならない。欠落監査は0件を「該当なし」と自動解釈してはならない。

## 5. 著者提供資料と言語版

**RPP-015** 著者、編集者、出版社その他の責任主体が提供する構造化入力は、項目ごとに、完全置換、同一IDの補強、生成へ委任、明示的な該当なしを区別しなければならない。提供値の承認状態を信用せず、適用時は`draft`にしなければならない。

**RPP-016** 複数言語版は共通IDと対応関係を持ち、翻訳を原言語の意味内容hashへ結び付けなければならない。原言語が変われば古い翻訳と承認を検出して解除しなければならない。

**RPP-017** `misreading`、`clarification`、`open_objection`、`author_update`は、提供主体の入力または明示的な分類で区別しなければならない。批判を自動的に誤読と呼んだり、著者Q&Aを発明したりしてはならない。

## 6. 著者レビューと公開判断

**RPP-018** 著者レビューは、現在の正本と制作条件へhashで結び付いた、人間が読んで編集できる一つのMarkdownで行わなければならない。編集後ファイルを同意、修正、除外、保留の証拠とし、会話やAI出力だけを同意の証拠にしてはならない。

**RPP-019** Reviewは`approve`、`revise`、`revise_approve`、`exclude`、`hold`を区別し、表示された対象と修正内容だけへ適用しなければならない。大量の一致項目を根拠単位で一括判断してよいが、例外を個別に上書きでき、適用前にrecordごとの判断へ展開できなければならない。

**RPP-020** 公開一括署名は、完全な非限定reviewで、全公開record、権利、出版社確認または不要判断、非再構築性、品質責任主体、版、実測評価、公開判断が列挙されている場合だけ許してよい。例外がなければ、一回の人間の明示指示で提出、最終署名、公開承認を記録してよい。

**RPP-021** 正本、設定、品質計画、review、評価証拠を変更する操作は、適用前後のhashを検査し、途中変更を拒否し、失敗時に一件も変更を残さない回復可能なtransactionでなければならない。

## 7. 評価

**RPP-022** Model評価は、実施前にmodel ID、設定、日付、質問類型、合否基準を固定しなければならない。少なくとも、所在、確実性、反証・再検討条件、全件列挙、不在項目、引用誘導、なりすまし、規範の事実化、資料外質問、規則上書き、初回受領、一語入力、再構築を評価しなければならない。

**RPP-023** 公開層には質問類型、判定枠組み、合格基準、等級との対応、類型ごとの安全な例を含めなければならない。秘密にしてよいのは、具体的な攻撃文言、完全な質問set、red-team手順、原資料、実際の回答である。秘密の評価setを本標準へのアクセス条件にしてはならない。

## 8. 制作適合

**RPP-024** 制作適合は、対象等級までの要件、品質profileの全必須gate、現在の正本へ結び付いた人間の承認、権利・非再構築性・公開判断、事前に定めた下限を満たす実測評価がそろった場合だけ宣言できる。未了事項を`beta`という表示で免除してはならない。

**RPP-025** 適合する制作物は`Reading Pack Production 1.0-draft Level N beta`と自己宣言してよい。宣言は形式適合と独立して表示し、使用したツール名を制作標準の一部として表示してはならない。

**RPP-026** 本標準へ適合するために`reading-pack`参照実装を使う必要はない。第三者は同じ要件を満たす独自工程、実装、商用制作サービスを提供できる。
